# ⑤ Reviewer — 代码评审

## 输入

由主 Agent 传入：
- 目标服务改动 diff
- **全部服务的知识文档**（检查跨服务调用是否正确）
- 目标服务类型（backend / frontend）

## 执行步骤

### 1. 获取目标服务 diff

```bash
cd <目标服务 local_path>
git diff main...feature/<分支>
```

### 2. 后端检查（type=backend）

| 检查维度 | 要点 |
|---------|------|
| 分层规范 | Controller 不写业务逻辑、Service 不直接拼 SQL |
| 事务 | `@Transactional` 范围合理、回滚覆盖 |
| SQL | 禁止 `SELECT *`、大表索引、无 N+1 |
| 参数校验 | `@Valid` / `@Validated` 到位 |
| 异常处理 | 全局异常捕获、不泄露敏感数据 |
| 安全 | SQL 注入、接口鉴权 |
| 性能 | 循环内不查库、无大事务 |

### 3. 前端检查（type=frontend）

| 检查维度 | 要点 |
|---------|------|
| 组件规范 | 单一职责、Props/Emits 类型完整 |
| 状态管理 | Store 使用合理 |
| API 调用 | 统一错误处理、loading/error 状态 |
| 性能 | 不必要重渲染、列表分页 |
| 安全 | XSS、敏感信息 |
| 路由 | 守卫鉴权、懒加载 |

### 4. 跨服务调用检查（附加维度）

当目标服务调用了其他服务时：
- 调用的接口路径是否与知识文档一致
- 请求参数和响应结构是否匹配
- 是否处理了被调用方不可用的降级场景

### 5. 评审结论

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 必须修复 | 返回 Coder |
| P1 | 应该修复 | 记录，建议修复 |
| P2 | 择机修复 | 记录 |

## 产出格式

产出写入 `runs/<task-id>/reviewer.md`：

```markdown
# 代码评审报告

## 目标服务: <service-name>

## 维度检查
| 维度 | 状态 | 问题 |
|------|------|------|

## 跨服务调用检查（如有）
| 调用 | 被调用方 | 检查结果 |
|------|---------|---------|

## 问题汇总
| 级别 | 文件 | 问题 | 修复建议 |
|------|------|------|---------|

## 结论
```
