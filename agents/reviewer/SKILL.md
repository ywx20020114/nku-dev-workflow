# ⑤ Reviewer — 代码评审

## 输入

由主 Agent 传入：
- 测试通过确认（tester.md）
- 后端改动 diff（如涉及）：`git diff main...feature/<分支>`
- 前端改动 diff（如涉及）：`git diff main...feature/<分支>`
- 双知识库文档（用于理解上下文）

## 执行步骤

### 1. 获取改动

分别获取后端和前端仓库的 diff。

### 2. 后端检查（如涉及后端改动）

| 检查维度 | 要点 |
|---------|------|
| 分层规范 | Controller 不写业务逻辑、Service 不直接拼 SQL |
| 事务 | `@Transactional` 范围合理、回滚覆盖写操作 |
| SQL | 禁止 `SELECT *`、大表索引、无 N+1 查询 |
| 参数校验 | `@Valid` / `@Validated` 到位 |
| 异常处理 | 全局异常捕获、错误信息不泄露敏感数据 |
| 安全 | SQL 注入（`${}` → `#{}`）、接口鉴权 |
| 性能 | 循环内不查库、无大事务长连接 |

### 3. 前端检查（如涉及前端改动）

| 检查维度 | 要点 |
|---------|------|
| 组件规范 | 单一职责、Props/Emits 类型完整、无直接 DOM 操作 |
| 状态管理 | Store 使用合理、无跨组件状态散落 |
| API 调用 | 统一错误处理、loading/error 状态覆盖 |
| 性能 | 列表虚拟滚动/分页、图片懒加载、无不必要的重渲染 |
| 安全 | XSS 防护（v-html 使用）、敏感信息不入前端代码 |
| 可访问性 | 表单 label 关联、按钮有 aria-label、键盘导航 |
| 路由 | 守卫鉴权、懒加载、404 处理 |

### 4. 评审结论

| 级别 | 定义 | 示例 |
|------|------|------|
| P0 严重 | 必须修复，阻塞上线 | SQL 注入、未处理的异常导致白屏 |
| P1 重要 | 应该修复 | 缺少 loading 状态、N+1 查询 |
| P2 建议 | 可择机修复 | 命名不清晰、组件可拆分 |

## 失败处理

发现 P0 问题时返回 Coder 修复，重新走 Compiler → Tester → Reviewer。
