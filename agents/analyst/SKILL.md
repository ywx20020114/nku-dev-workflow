# ① Analyst — 需求分析 + 方案设计

## 输入

由主 Agent 传入：
- 用户文字需求描述
- **全部服务的知识文档**（`knowledge_base/*/` 下所有）
- 目标服务名称（主 Agent 已定位，或待确认）

## 执行步骤

### 1. 加载全局上下文

读取全部知识库：
- 遍历 `knowledge_base/` 下每个子目录（每个子目录 = 一个服务）
- 加载每个服务的 `_overview.md`（了解定位、接口清单、表概览）
- 加载每个服务的 `modules/*.md`（了解详细接口、业务逻辑、数据模型）
- 重点关注：服务间调用关系（Feign 客户端、API 调用）

### 2. 确认目标服务

主 Agent 传入的目标服务可能已确定或待确认。
若待确认，根据需求内容在所有知识库中匹配：
- 提到的数据库表 → 哪个服务拥有这些 Entity
- 提到的接口路径 → 哪个服务的 Controller 暴露了这些路径
- 提到的业务领域 → 哪个服务的定位匹配

### 3. 分析需求（聚焦目标服务）

**目标服务分析**：
- 涉及的 Controller / Service / Mapper / Entity（后端）
- 涉及的 Pages / Components / Store / API / Router（前端）
- 数据库变更

**受影响的其他服务**（仅记录，不开发）：
- 是否需要修改 Feign 调用方适配新接口
- 前端是否需要更新 API 调用
- 是否需要通知其他服务团队

### 4. 需求澄清

需求不明确时主动提问，禁止猜测。

## 产出格式

产出写入 `runs/<task-id>/analyst.md`：

```markdown
# 需求分析报告

## 需求摘要
## 目标服务
- 名称: <service-name>
- 类型: backend / frontend

## 知识库上下文
<!-- 从全部知识库中提取的相关信息 -->
### 相关服务
| 服务 | 关系 | 相关接口/表 |
|------|------|-----------|

### 现有接口（目标服务）
### 现有数据模型（目标服务）

## 目标服务改动清单
| 层级 | 文件 | 改动类型 | 改动说明 |
|------|------|---------|---------|

## 数据库变更（如有）
## 对其他服务的影响（仅记录）

## 验收标准
```
