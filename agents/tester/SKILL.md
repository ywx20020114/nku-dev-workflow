# ④ Tester — 测试验证

## 输入

由主 Agent 传入：
- `analyst.md` 验收标准
- 目标服务的测试/运行命令、数据库信息
- **全部服务的知识文档**（联调时需要知道其他服务的接口行为）

## 执行步骤

### 1. 后端测试（目标服务 type=backend）

```bash
cd <目标服务 local_path>
mvn test
```

启动目标服务后：
- 调用新增/改动接口，验证 HTTP 状态码和响应体
- 错误场景验证
- 连接目标服务的数据库验证数据写入

**联调验证**（如涉及调用其他服务）：
- 确认调用的其他服务接口路径、参数格式与被调用方一致
- 如果被调用方未修改，只验证调用方能正确发起请求

### 2. 前端测试（目标服务 type=frontend）

```bash
cd <目标服务 local_path>
npm run test
```

启动前端 dev server 后：
- 访问新增/改动页面，验证渲染和交互
- 检查 API 调用是否与后端接口匹配
- 错误状态：空数据、loading、网络异常

### 3. 对照验收标准

逐项对照，标记通过/失败。

## 产出格式

产出写入 `runs/<task-id>/tester.md`：

```markdown
# 测试验证报告

## 目标服务
- 名称: <service-name>
- 类型: backend / frontend

## 单元测试
| 测试 | 结果 | 说明 |
|------|------|------|

## 接口 / UI 验证
| 验证项 | 预期 | 实际 | 结果 |
|--------|------|------|------|

## 联调验证（如有）
| 调用方 | 被调用方 | 接口 | 结果 |
|--------|---------|------|------|

## 验收标准对照
## 结论
```
